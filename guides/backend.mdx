## Overview

The CrossConnect-Phos backend is built with NestJS, a progressive Node.js framework. This guide covers the backend structure, development workflow, and how to extend functionality.

## Core concepts

### Modules

NestJS uses modules to organize code. Each feature has its own module that encapsulates related controllers, services, and providers.

**Example module structure:**

```typescript
@Module({
  imports: [HttpModule],
  controllers: [ShopifyController],
  providers: [ShopifyService, ShopifyMapper],
  exports: [ShopifyService],
})
export class ShopifyModule {}
```

### Controllers

Controllers handle incoming HTTP requests and return responses.

**Location:** `backend/src/connectors/[platform]/[platform].controller.ts`

**Example:**

```typescript
@Controller('shopify')
export class ShopifyController {
  constructor(private readonly shopifyService: ShopifyService) {}

  @Get('products')
  async getProducts(@Query('storeId') storeId: string) {
    return this.shopifyService.fetchProducts(storeId);
  }
}
```

### Services

Services contain business logic and interact with external APIs or databases.

**Location:** `backend/src/connectors/[platform]/[platform].service.ts`

**Actual Shopify service example:**

```typescript
@Injectable()
export class ShopifyService {
  private readonly logger = new Logger(ShopifyService.name);
  private client: GraphQLClient;
  private shop: string;
  private accessToken: string;
  private apiVersion = '2026-01';

  constructor(private crypto: CryptoService) {}

  /* Initialize with encrypted credentials */
  initialize(credentials: any): void {
    this.shop = this.crypto.decrypt(credentials.shopDomain);
    this.accessToken = this.crypto.decrypt(credentials.accessToken);

    if (!this.shop || !this.accessToken) {
      throw new Error('Critical Shopify Configuration Missing');
    }

    this.client = new GraphQLClient(
      `https://${this.shop}/admin/api/${this.apiVersion}/graphql.json`,
      {
        headers: {
          'X-Shopify-Access-Token': this.accessToken,
          'Content-Type': 'application/json',
        },
      }
    );
  }

  /* Fetch products with retry logic */
  async fetchProducts(): Promise<ShopifyProductNode[]> {
    const data = await this.execute<FetchProductsQuery>(
      FETCH_PRODUCTS,
      undefined,
      'fetchProducts'
    );

    return data?.products?.nodes || [];
  }

  /* Execute GraphQL with exponential backoff */
  private async withRetry<T>(
    fn: () => Promise<T>,
    context: string,
    maxRetries = 5,
    baseDelayMs = 1000,
  ): Promise<T> {
    let attempt = 0;

    while (true) {
      try {
        return await fn();
      } catch (err: any) {
        attempt++;
        const status = err?.response?.status;
        const isThrottle = err?.response?.errors?.some(e =>
          String(e.message).toLowerCase().includes('throttle')
        );

        const retryable = status === 429 || status >= 500 || isThrottle;

        if (!retryable || attempt > maxRetries) {
          throw err;
        }

        const backoff = baseDelayMs * Math.pow(2, attempt - 1) +
          Math.floor(Math.random() * 300);

        this.logger.warn(
          `Shopify retry ${attempt}/${maxRetries} in ${backoff}ms`
        );

        await this.sleep(backoff);
      }
    }
  }
}
```

**Key features:**
- **Credential decryption** — Uses CryptoService to decrypt stored credentials
- **GraphQL client** — Uses `graphql-request` for Shopify Admin API
- **Retry logic** — Exponential backoff with jitter for rate limits
- **API versioning** — Currently using Shopify API version 2026-01

### Repositories

Repositories handle database operations with Supabase using `nestjs-supabase-js`.

**Location:** `backend/src/supabase/repositories/`

**Actual StoresRepository example:**

```typescript
@Injectable()
export class StoresRepository {
  private logger = new Logger(StoresRepository.name);

  constructor(
    @InjectSupabaseClient()
    private readonly supabaseClient: SupabaseClient<Database>,
  ) {}

  async getAllActiveStores(): Promise<Database['public']['Tables']['stores']['Row'][]> {
    const { data, error } = await this.supabaseClient
      .from('stores')
      .select('*')
      .eq('auth_status', 'active');

    if (error) {
      this.logger.error('Failed to fetch active stores', error);
      throw error;
    }

    return data || [];
  }

  async updateStoreHealth(
    storeId: string,
    status: 'healthy' | 'unhealthy',
    message?: string,
  ): Promise<void> {
    const { error } = await this.supabaseClient
      .from('stores')
      .update({
        last_health_check: new Date().toISOString(),
        auth_status: status === 'healthy' ? 'active' : 'inactive',
      })
      .eq('id', storeId);

    if (error) {
      this.logger.error(`Failed to update store health`, error);
    }

    // Create alert if unhealthy
    if (status === 'unhealthy') {
      await this.createAlert(
        storeId,
        'store_health_check',
        message || 'Store connection failed',
        'high',
      );
    }
  }

  async updateWebhookStatus(storeId: string, status: boolean): Promise<void> {
    const { error } = await this.supabaseClient
      .from('stores')
      .update({
        webhook_status: status,
        auth_status: status ? 'active' : 'inactive',
      })
      .eq('id', storeId);

    if (error) {
      this.logger.error(`Failed to update webhook status`, error);
    }
  }

  async storesAsQueued(storeIds: string[]) {
    const now = new Date().toISOString();

    return await this.supabaseClient
      .from('stores')
      .update({
        last_health_check: now,
        auth_status: 'active',
      })
      .in('id', storeIds);
  }
}
```

**Key patterns:**
- **Type safety** — Uses generated Supabase types
- **Error logging** — Logs all database errors
- **Bulk operations** — Uses `.in()` for batch updates
- **Alert integration** — Creates alerts on failures
- **Health tracking** — Updates timestamps and status

## Adding a new connector

To add support for a new marketplace or warehouse platform:

<Steps>
  <Step title="Create the module directory">
    ```bash
    mkdir -p src/connectors/newplatform
    ```
  </Step>

  <Step title="Create the module files">
    Create the following files:
    - `newplatform.module.ts` — Module definition
    - `newplatform.controller.ts` — API endpoints
    - `newplatform.service.ts` — Business logic
    - `newplatform.mapper.ts` — Data transformation
    - `newplatform.types.ts` — TypeScript types
  </Step>

  <Step title="Implement the service">
    ```typescript newplatform.service.ts
    @Injectable()
    export class NewPlatformService {
      async fetchProducts(credentials: StoreCredentials) {
        // Implement API calls to the platform
      }

      async fetchOrders(credentials: StoreCredentials) {
        // Implement order fetching
      }
    }
    ```
  </Step>

  <Step title="Register the module">
    Add your module to `ConnectorsModule`:

    ```typescript connectors.module.ts
    @Module({
      imports: [
        // ... existing connectors
        NewPlatformModule,
      ],
    })
    export class ConnectorsModule {}
    ```
  </Step>

  <Step title="Add job processor">
    Create a processor in `src/jobs/` to handle background sync:

    ```typescript
    @Processor('newplatform-products')
    export class NewPlatformProductsProcessor {
      @Process()
      async handleProductSync(job: Job) {
        // Process the job
      }
    }
    ```
  </Step>
</Steps>

## Working with jobs

### Creating a job

Enqueue a job from any service:

```typescript
import { InjectQueue } from '@nestjs/bull';
import { Queue } from 'bull';

@Injectable()
export class MyService {
  constructor(
    @InjectQueue('products') private productsQueue: Queue,
  ) {}

  async syncProducts(storeId: string) {
    await this.productsQueue.add('sync', {
      storeId,
      timestamp: new Date(),
    });
  }
}
```

### Processing a job

Create a processor to handle jobs:

```typescript
import { Processor, Process } from '@nestjs/bull';
import { Job } from 'bull';

@Processor('products')
export class ProductsProcessor {
  @Process('sync')
  async handleSync(job: Job) {
    const { storeId } = job.data;
    
    // Perform sync logic
    await this.syncProductsForStore(storeId);
    
    return { success: true };
  }
}
```

## Database operations

### Using repositories

Always use repositories for database operations:

```typescript
@Injectable()
export class MyService {
  constructor(
    private readonly storesRepository: StoresRepository,
  ) {}

  async getActiveStores() {
    return this.storesRepository.findActive();
  }
}
```

### Creating a new repository

<Steps>
  <Step title="Create the repository file">
    ```bash
    touch src/supabase/repositories/my-entity.repository.ts
    ```
  </Step>

  <Step title="Implement the repository">
    ```typescript
    @Injectable()
    export class MyEntityRepository {
      constructor(
        @Inject('SUPABASE_CLIENT')
        private readonly supabase: SupabaseClient,
      ) {}

      async findAll() {
        const { data, error } = await this.supabase
          .from('my_entity')
          .select('*');

        if (error) throw error;
        return data;
      }
    }
    ```
  </Step>

  <Step title="Register in SupabaseModule">
    Add to the providers array in `supabase.module.ts`.
  </Step>
</Steps>

## Logging

CrossConnect-Phos uses `nestjs-pino` for structured logging.

### Using the logger

```typescript
import { Logger } from '@nestjs/common';

@Injectable()
export class MyService {
  private readonly logger = new Logger(MyService.name);

  async doSomething() {
    this.logger.log('Starting operation');
    
    try {
      // ... operation
      this.logger.log('Operation completed successfully');
    } catch (error) {
      this.logger.error('Operation failed', error.stack);
    }
  }
}
```

### Log levels

- `logger.log()` — General information
- `logger.debug()` — Detailed debugging information
- `logger.warn()` — Warning messages
- `logger.error()` — Error messages with stack traces

## Testing

### Unit tests

Create unit tests alongside your code:

```typescript my-service.spec.ts
describe('MyService', () => {
  let service: MyService;

  beforeEach(async () => {
    const module: TestingModule = await Test.createTestingModule({
      providers: [MyService],
    }).compile();

    service = module.get<MyService>(MyService);
  });

  it('should be defined', () => {
    expect(service).toBeDefined();
  });

  it('should fetch products', async () => {
    const result = await service.fetchProducts('store-123');
    expect(result).toHaveLength(10);
  });
});
```

Run tests:

```bash
npm run test
```

### E2E tests

E2E tests are located in the `test/` directory:

```typescript app.e2e-spec.ts
describe('AppController (e2e)', () => {
  let app: INestApplication;

  beforeEach(async () => {
    const moduleFixture: TestingModule = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();

    app = moduleFixture.createNestApplication();
    await app.init();
  });

  it('/api/health (GET)', () => {
    return request(app.getHttpServer())
      .get('/api/health')
      .expect(200);
  });
});
```

Run E2E tests:

```bash
npm run test:e2e
```

## Best practices

<AccordionGroup>
  <Accordion title="Use dependency injection">
    Always inject dependencies through constructors rather than creating instances manually.
  </Accordion>

  <Accordion title="Handle errors properly">
    Use try-catch blocks and throw appropriate HTTP exceptions:
    ```typescript
    throw new NotFoundException('Store not found');
    ```
  </Accordion>

  <Accordion title="Validate input">
    Use DTOs with class-validator decorators:
    ```typescript
    export class CreateProductDto {
      @IsString()
      @IsNotEmpty()
      name: string;

      @IsNumber()
      @Min(0)
      price: number;
    }
    ```
  </Accordion>

  <Accordion title="Use environment variables">
    Never hardcode configuration values. Use the ConfigService:
    ```typescript
    constructor(private configService: ConfigService) {}

    getApiKey() {
      return this.configService.get<string>('API_KEY');
    }
    ```
  </Accordion>

  <Accordion title="Keep services focused">
    Each service should have a single responsibility. Split large services into smaller, focused ones.
  </Accordion>
</AccordionGroup>
